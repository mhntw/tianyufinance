# 酒店经营台账（网页版）

专为连锁酒店加盟店财务日常记账设计，纯前端、零依赖、本机离线运行。

## 关于产品来源（开发者须知）

本软件的开发灵感与界面参考来源于 **金蝶精斗云·云会计**——版面布局、功能板块、
交互文案与会计科目体系均以其为参照。它已是一款成熟产品，我们的目标是对齐而非改造。

由此产生两条贯穿全项目的约定，改动代码前请先了解：

1. **注释约定**：代码注释里的溯源表述（「复刻金蝶」「对标金蝶」「（金蝶：xxx）」等）
   已统一收敛到本节，注释中不再重复。目前代码中残留的「金蝶」只出现在三类地方，
   都是**有意为之，请勿再清理或扩散**：
   - **源码定位坐标**：如 `金蝶源码/…chunk.js`、HTML 注释里的 `L115` 行号、CSS 类名
     （`.accountName`、`contentItemWrapper--1cQtp`）——改版时对照参考实现要用；
   - **数据格式名**：`金蝶 KIS`、`.ais`——这是功能本身，不是溯源；
   - **用户可见文案**：如提示"重新导入金蝶账套"——面向用户，改了反而看不懂。
2. **数据互通**：科目编码已与精斗云对齐
   （1001/1002/1122/2202/1405/6401/6001/5601/2211/2001…），
   支持与精斗云互导 Excel，也支持导入金蝶 KIS 的 `.ais` 账套。

> 参考源码的阅读方式见文末「金蝶源码阅读机制」。

## 如何使用
- **Windows**：双击 `启动.bat`，直接打开 `index.html`（`file://` 协议，零进程零端口，安全软件不拦截；首次使用建议在「设置 - 数据与安全」导出备份）。
- **Mac 开发/优化**：双击 `启动.command`，会起一个零业务的本地静态服务（`http://localhost:8011`），浏览器跑在 `localhost` 下即可启用「真实文件落盘」（File System Access API），数据与目标机行为一致。
- 也可直接双击 `index.html` 打开，但 `file://` 下仅走浏览器 IndexedDB 兜底（清缓存会丢，需定期手动导出），仅建议临时查看。
2. 顶部「当前门店」可切换三家加盟店；所有记账按门店隔离。
3. 账套数据在软件目录内 `data/books/<id>.json`（真相源），自动备份在 `data/backups/`；拷贝/迁移整个 `rj/` 目录即可带走软件与数据。

## 功能模块（全复式闭环）
所有业务最终都落地为**复式凭证**，三张报表统一从科目余额取数，不存在"单式流水 + 复式账"双轨：
- **记账凭证（复式借贷）**：点「记一笔」录入**复式凭证**——每行选「会计科目 + 借/贷 + 金额」，可加多行；系统实时校验**借贷必相等**，不平衡无法保存。
- **应收应付**：新增往来即自动生成凭证（应收：借 1122 / 贷 6001；应付：借 5601 / 贷 2202）；「结清」再生成收付款凭证（借/贷银行 + 借/贷 1122/2202）。应收/应付科目余额直接来自凭证。
- **库存管理**：出入库即自动生成凭证（入库采购到货：借 1405 库存商品 / 贷 2202 应付账款，货款在「应付」模块付清；出库结转成本：借 6401 主营业务成本 / 贷 1405 库存商品），存货 1405 与利润表成本均真实反映。
- **工资管理**：保存即自动生成凭证——计提（借 5601 / 贷 2211）+ 发放（借 2211 / 贷 银行）+ 单位社保（借 5601 / 贷 银行）。
- **借款管理**：借入登记自动生成凭证（借 银行 / 贷 2001，筹资活动）；偿还再生成凭证（借 2001 / 贷 银行）。
- **报表统计**：选择「当前门店」或「全部门店合并」，按月份汇总。三张表全部从**科目余额**取数：
  - **利润表（本月）**：营业收入 − 营业成本及费用 = 利润总额。
  - **资产负债表（存量快照）**：截至所选月份，**资产 = 负债 + 所有者权益** 恒等式，由借贷平衡保证恒等，并做平衡校验。
  - **现金流量表（本月）**：按经营 / 筹资 / 投资三大活动分类汇总现金流入流出（凭证指定现金流量项目）。
- **期初余额（开账录入）**：在「门店管理」页内，按标准科目逐项录入期初余额（资产/费用填借方，负债/权益/收入填贷方），保存时校验**期初借贷平衡**。
- **银行存款辅助核算**：银行账户（库存现金/对公户/老板个户/微信）是 **1002 银行存款的辅助核算项**，仅作档案、用于凭证选择「哪个银行账户」；余额统一从 1001/1002 科目由凭证汇总得出，不另立账户余额体系。
- **对账**：以某银行账户为对象，账面余额直接由 1001/1002 科目凭证汇总得到，与对账单余额比对差异，无需手工录入账面余额。
- **门店管理**：切换门店无需密码；但**新增 / 改名（编辑）/ 删除门店**需输入管理密码（见下），删除门店会同时清除其账目，谨慎操作。
- **金蝶精斗云 数据互通（双向打通）**：在「数据备份」页底部，可与金蝶精斗云云会计互导 Excel：
  - **从金蝶导入（xlsx）**：选金蝶导出的 Excel（含「凭证导入模板」和/或「科目余额表」两种表），自动识别并**同时导入逐笔凭证 + 科目余额（作期初）**；重复凭证（同凭证字+号+日期）自动跳过；银行存款科目的核算项目尽量映射回本店银行档案；操作需管理密码。
  - **导出凭证（xlsx）**：生成精斗云「凭证导入模板」格式 Excel，可直接在金蝶里导入。
  - **导出科目余额（xlsx）**：生成精斗云「科目余额表」格式 Excel，可作金蝶期初导入。
  - 科目编码已对齐金蝶（1001/1002/1122/2202/1405/6401/6001/5601/2211/2001…），导入时科目代码直接沿用，无需映射。
- **数据备份 / 恢复**：自动备份落磁盘（`data/backups/`，环形轮换）+ 离线 IndexedDB 兜底；「设置 → 数据与安全」可手动导出/导入账套（JSON）、一键导出全部账套。

## 门店管理密码
- 新增、改名、删除门店、新增/编辑/删除银行账户时会弹出密码框，验证通过才执行。
- 密码在 `js/store.js` 顶部 `ADMIN_PASSWORD` 常量中设置（默认占位 `__CHANGE_ME__`，请改成你自己的密码，并勿外泄）。
- 日常记账（凭证、应收应付、库存、工资、借款、报表）不需要密码，不影响录账效率。

## 标准会计科目（可自由增删）
五大要素：资产 / 负债 / 权益 / 收入 / 费用。默认科目含：
- 资产：库存现金(1001)、银行存款(1002)、应收账款(1122)、预付账款(1123)、库存商品(1405)、固定资产(1601)、累计折旧(1602)
- 负债：应付账款(2202)、预收账款(2203)、短期借款(2001)、应付职工薪酬(2211)、应交税费(2221)
- 权益：实收资本(3001)、利润分配(3101)
- 收入：主营业务收入(6001)、其他业务收入(6051)
- 费用：销售费用(5601)、管理费用(5602)、财务费用(5603)、主营业务成本(6401)

记账时选科目即定要素与借贷方向（资产/费用借增，负债/权益/收入贷增）。如需新增科目，可在「门店管理 → 期初余额」下方的科目体系基础上，于 `store.js` 的 `DEFAULT_ACCOUNTS` 扩展。

## 关于复式借贷引擎
本软件为**纯复式借贷记账**，与主流财务软件同一套逻辑，财务无需学习第二套：
- **借贷必相等**：每张凭证至少一借一贷，借贷金额相等才能保存，自动防错防弊。
- **业务即凭证**：应收应付、库存、工资、借款等业务操作在保存时自动生成对应复式凭证，资产负债表应收/应付/存货/负债等科目真实反映业务，无"四不像"双轨。
- **三张表自动生成**：利润表、资产负债表、现金流量表均由「科目余额」直接取数。
- **资产负债表恒等式**：资产 = 负债 + 所有者权益，由借贷平衡保证恒等，无需手工凑数。
- **期初借贷平衡**：开账录入期初余额时校验借贷平衡，防止开账错误。

新账套开账流程：① 在「门店管理 → 期初余额」按科目录入期初（含实收资本 3001、期初应收 1122、期初应付 2202）；② 日常用「记一笔」录复式凭证，或通过各业务模块录单（自动生成凭证）；③ 报表页直接看三张表。

## 未来打包（Tauri / Electron）
当前为「纯前端 + js/storage.js 存储引擎」架构，数据层集中在 `js/storage.js` 的 `Storage` 对象（已对 `js/store.js` 暴露统一 `/api/*` 等价接口）。
若后续要打包成桌面安装版：前端 JS 业务逻辑可原样复用，仅需给 `Storage` 注入一个原生适配器
（Tauri Rust 命令 / Electron Node `fs` 实现 `fsSaveBook`/`fsLoadBook` 等），业务代码零改动。
页面逻辑无需改动。

## 目录结构（纯本地版）
```
rj/                          # 软件本体（本目录，运行时所需文件全部在内）
├── index.html               # 页面与弹窗结构（单栏首页，无云端占位）
├── css/style.css            # 样式
├── js/                      # 前端逻辑
│   ├── main.js              # 入口（ESM 模块装配）
│   ├── app.js               # 应用壳（路由/事件/顶栏）
│   ├── store.js             # 数据层（账套读写/持久化调度，调用 Storage）
│   ├── storage.js           # 纯前端存储引擎（替代原 serve.py 的 /api/* 文件读写）
│   ├── pages/               # 页面模块（home/voucher/report/settings…）
│   ├── kis-import.js        # 金蝶 .ais 账套导入转换
│   ├── mdb-reader.js        # MDB(.ais) 只读解析
│   └── 依赖：echarts.min.js / xlsx.full.min.js / kd-menu-icons.js / buffer.js / kindee.js
├── data/                    # 账套数据（随软件运行自动生成）
│   ├── books/<id>.json      # 多账套真相源（每个账套一个 JSON 文件）
│   └── backups/             # 自动备份快照（按账套目录 + 环形轮换）
├── 启动.command / 启动.bat  # 启动脚本（Mac 起 localhost 静态服务；Windows 直接打开 index.html）
└── README.md
```

数据目录定位规则（storage.js）：优先 `FISCAL_DATA_DIR` 环境变量 → 其次软件目录内 `data/`；`file://` 下降级浏览器 IndexedDB。
本软件为纯本地单机版，不依赖云端、无需登录、无外部数据源；页面关闭/刷新前的最终落盘有兜底机制，期末高风险操作（结账/结转损益等）会强制立即备份。

## 金蝶源码阅读机制（开发者必读）
金蝶参考源码全部是**单行压缩 HTML（一行可 11 万字符）和 webpack 压缩 JS（变量 a/b/c）**，直接读必然爆上下文且读不懂。
已建立"蒸馏"机制，**一律不直接读原始压缩源码**：

1. 入口：`金蝶源码/INDEX.md`（总地图，先读它）
2. 定位：`grep <中文关键词> 金蝶源码/distilled/index/<文件>.index.md` → 得行号
3. 精准读：`read_file(金蝶源码/distilled/format/<文件>.html, offset=行号±5, limit=40)`
4. 页面结构已蒸馏成知识库：`金蝶源码/页面结构/*.md`（组件树+源码位置+本项目落点）

重建蒸馏产物：`python3 tools/kingdee_distill.py all`
铁律：**先找金蝶源码复刻，禁止自行发明实现**（UI/文案/交互对齐金蝶）。

## 迁移页面裸引用体检（开发者必读）

ESM 页面（`js/pages/**`）统一从全局 `__KINGDEE_HELPERS__`（app.js 注册）/ `__KINGDEE_EXPORT__`
（store.js 注册）取依赖。若某页面**用了某符号却既未本地定义、又未 import、又不以
`H.`/`EX.`/`S.`/`U.`/`window.` 形式命名访问**，会在模块作用域抛 `ReferenceError`
（如曾发生 `currentPeriod is not defined`）。

迁移/新增页面后，请运行体检确认自足：

```bash
python3 tools/check_pages.py     # 有隐患时打印并返回非零退出码；全绿返回 0
```

脚本只识别已知桥接 helper/方法名，重点防“漏绑定”这类高频回归；任意新符号仍靠 review 把关。
