# 添钰财务管理系统

本地单机的桌面财务记账软件（Tauri 2 + 原生系统 WebView，**无需联网、无需登录、无云端依赖**）。
专为小微企业与个体经营设计，采用标准**复式借贷记账**，账套以真实文件保存在本机，
支持结账/结转损益/年结等完整期末流程，并与金蝶生态（KIS `.ais` / 精斗云 Excel）双向互通。

> 交互与科目体系参照金蝶精斗云·云会计，数据层面与其对齐，便于习惯金蝶的用户零成本上手。

---

## 功能一览

- **记账凭证（复式借贷）**：逐行选「科目 + 借/贷 + 金额」，系统实时校验**借贷必相等**，不平不能保存；凭证字号自动管理，支持跨月查重、回收站（删除保留 7 天可还原）。
- **会计科目**：开账即预置标准科目（按准则模板），科目可自由增删改；**已被凭证/期初余额使用的科目禁止改类别**（防历史数据错乱）。
- **账务账簿**：科目余额、明细账、多栏账、试算平衡（含逐月试算校验），全部从凭证逐笔派生。
- **财务报表**：资产负债表、利润表、现金流量表、费用明细、项目利润等，**统一从科目余额取数**，三大表口径勾稽一致。
- **期末处理**：期末结转模板（计提折旧/工资、转出增值税、计提附加税/所得税等，可自选启用）、**结账/反结账**、结转损益、年末结转本年利润；期末业务凭证以类型标记识别，天然防重复生成。
- **固定资产与工资**：资产卡片 + 按月计提折旧自动生成凭证；工资计提/发放自动入账。
- **数据互通**：导入金蝶 KIS 账套（`.ais` / Excel）、与精斗云云会计互导「凭证/科目余额」Excel；科目编码已对齐金蝶（1001/1002/1122/2202/1405/6401/…），导入无需映射。
- **多账套与数据安全**：一机多账套相互隔离；自动备份（环形轮换）+ 高风险操作强制即时备份 + 手动导出 JSON 三重保障；账套文件格式跨 Windows / macOS 通用。

## 安装与获取安装包

软件为桌面应用，按平台取安装包（浏览器仅用于开发预览，不出在线版）：

| 平台 | 产物 | 构建方式 |
|---|---|---|
| Windows | `*-setup.exe`（NSIS x64） | **GitHub Actions 云端自动构建** |
| macOS | `.app` / `.dmg` | 本机 `tauri/` 目录 `npm run tauri build` |

### Windows 安装包：GitHub Actions 自动打包

工作流 `.github/workflows/windows-build.yml`，两种触发方式、产物去向不同：

| 触发方式 | 操作 | 产物去哪 |
|---|---|---|
| 手动预览 | Actions →「Windows 打包」→ **Run workflow** | 仅该次运行记录的 **Artifacts**（不生成 Release） |
| 正式发布 | 推送 `v` 开头的 tag | **自动发布为正式 Release** 并挂上安装包（无需手动 Publish） |

正式发布一条命令（**tag 必须与 `tauri/src-tauri/tauri.conf.json` 的 `version` 一致**）：

```bash
git tag v1.0.1 && git push origin v1.0.1
```

云端构建约 10~20 分钟后，到仓库 **Releases** 页可见 `v1.0.1`，从 Assets 下载 `*-setup.exe` 即可分发。

### macOS 安装包：本机构建

```bash
cd tauri
npm install           # 首次
npm run tauri build   # 产物在 src-tauri/target/release/bundle/dmg 与 .../macos
```

### 日常发布入口（推荐）

双击根目录「发布新版.command」（仅本机本地脚本，未入库）即可完成上两节的全部操作：

- **日常存档**：第 3 步直接回车 → 提交并推送代码
- **出 Windows 正式版**：第 3 步输 `y` → 自动 bump 版本号 + 打 tag → GitHub 自动打包并发布 Release
- **出 macOS 包**：第 4 步输 `y` → 本机自动打包

### 常见问题

- **手动 Run 之后找不到安装包？** 手动 Run 的产物只在运行记录底部 **Artifacts**，不会进 Release；想进 Release 用上面的 tag 方式。
- **版本号怎么定？** 打 tag 前先确认 `tauri.conf.json` 的 `version` 与 tag 一致（如 tag `v1.0.1` ↔ version `1.0.1`）。
- **前端改了没生效？** `tauri build` 前会由 `scripts/build-dist.mjs` 自动同步前端到打包源，无需手动维护。

## 数据存储位置（重要）

账套与备份均保存在**操作系统的应用数据目录**，随软件自动创建：

| 平台 | 路径 |
|---|---|
| macOS | `~/Library/Application Support/添钰财务/` |
| Windows | `%APPDATA%\添钰财务\`（即 `C:\Users\<用户>\AppData\Roaming\添钰财务\`） |
| Linux | `~/.local/share/添钰财务/` |

目录内：`books/`（账套主文件）、`backups/`（自动备份 + 恢复前快照）、`trash/`（回收站，7 天清理）、`exports/`（手动导出的可携带 JSON）、`attachments/`（凭证附件）、`changelog.json`、`meta.json`。

> 目录名「添钰财务」是**固定定位锚点**，软件刻意不随界面品牌/程序标识变化——改一次会让已装用户的账套全部"找不到"（后端有守门单测）。软件内「设置 → 打开数据目录」可直接打开该位置。

**备份与迁移**：把上面整个目录拷走即完成全部数据迁移；日常可在软件内导出账套 JSON 留 U 盘/网盘副本。切勿把数据目录放进 OneDrive/网盘等自动同步目录，多设备同时读写会产生冲突副本。

## 本地开发与预览

```bash
cd tauri
npm install        # 首次
npm run tauri dev  # 打开桌面调试窗口，前端热改即时生效
```

改前端只需动仓库根 `index.html` / `css/` / `js/`，`tauri/` 为桌面打包壳，无需手动维护打包源。

## 目录结构

```
├── index.html / css/ / js/   # 前端主体（js/pages/** 为各业务模块页面）
│   ├── store.js              # 数据层核心（账套读写 / 业务规则 / 期末引擎）
│   ├── kis-import.js         # 金蝶 KIS(.ais/Excel) 账套导入
│   └── pages/                # 凭证 / 科目 / 账薄 / 报表 / 资产 / 工资 / 期末 / 设置
├── tauri/                    # Tauri 2 桌面壳
│   ├── src-tauri/            # Rust：文件读写 / 备份 / 附件 / 数据目录
│   ├── scripts/build-dist.mjs# 打包前把最新前端同步到 dist/（跨平台 Node 脚本）
│   └── WINDOWS_BUILD.md      # Windows 本地打包手册（可选，已由 CI 取代日常使用）
├── tools/                    # 验证与诊断脚本（审计 / 不变量 / 兼容性自检）
├── .github/workflows/        # GitHub Actions：Windows 自动打包
├── CHANGELOG.md              # 变更记录（功能演进与缺陷修复历史）
└── README.md
```

## 开发约定与质量基线

- **单一事实源**：报表/结转/幂等判断一律以凭证类型标记 `v.kind` 与科目角色为准，**禁止再用摘要正则判定业务凭证**（历史教训，见 `CHANGELOG.md`）。
- **数据绝不外流**：账套、备份等数据文件由 `.gitignore` 红线保护，仓库中无任何真实账套数据。
- **验证体系**：`tools/` 下保留全套回归脚本（不变量审计、稳定性测试、金蝶导入兼容自检、幂等验证等），改动高风险逻辑后跑对应脚本。
