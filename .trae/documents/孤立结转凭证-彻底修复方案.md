# 「孤立结转凭证」彻底修复方案

## Context

### 问题（已取证，可复现）
「录费用凭证 → 结转损益 → 删除那张原费用凭证」后（未结账期删除是合规操作），同一个状态被两条不同口径判成**相反结论**，用户被踢皮球：

```
① 录入费用凭证 记-1（5401 借 2190）
② 结转损益 → 生成 记-2
③ 删除原费用凭证 → ok
④ 结账检查 carry → fail「本期损益未结转，请先结转损益」
⑤ 再点结转     → fail「本期损益已结转，请勿重复；如需重做请先删除结转凭证（记-2）」
⑦ 直接结账     → 被 carry 拦截
```

复现：`node tools/test_newbook_fuzz.js --seed 777`；`tools/test_newbook_fuzz.js` 已用确定性用例锁住该场景。

### 根因
`carryForwardState()`（≈[store.js L2560](file:///Users/chen/财务软件/ty/js/store.js#L2560)：**是否存在 carryPL 凭证**）与 `periodProfitNet()`（≈[store.js L2544](file:///Users/chen/财务软件/ty/js/store.js#L2544)：**本期损益净额是否为零**）是两个各自正确的口径，但**消费方没有交叉判断**：

| 消费方 | 位置 | 现状 |
|---|---|---|
| `settleChecklist` carry 项 | [store.js L2905-L2912](file:///Users/chen/财务软件/ty/js/store.js#L2905-L2912) | 只看 `periodProfitNet` → 「未结转」 |
| `carryForwardProfit` 幂等分支 | [store.js L2577-L2581](file:///Users/chen/财务软件/ty/js/store.js#L2577-L2581) | 只看 `carryForwardState` → 「已结转请勿重复」 |
| Settle.js 批量生成 | [Settle.js L342-L343](file:///Users/chen/财务软件/ty/js/pages/settle/Settle.js#L342-L343) | 只看 `periodVouchersOfKind` 是否存在 → **静默跳过** |

同类语义其实**已有既有范式**：[红字冲销 L2135-L2185](file:///Users/chen/财务软件/ty/js/store.js#L2135-L2185) 已用「`carryBefore && 原本结平 && 现在不结平`」判断"打破了已完成的损益结转"，并在 `hint` 里指引「请到 结账→期末处理 重新结转」。本次修复即把该判定**收敛成单点函数**，供三处共用。

### 附带发现的真实 UX 缺陷
UI 的「重新结转」按钮（[Settle.js L190-L214](file:///Users/chen/财务软件/ty/js/pages/settle/Settle.js#L190-L214)）已实现"删旧 + 重做"。但在孤立结转下点它：删掉旧结转凭证后本期已无损益 → `carryForwardProfit` 返回 `{ok:false,msg:'本期损益净额为零，无需结转'}` → [L209](file:///Users/chen/财务软件/ty/js/pages/settle/Settle.js#L209) `showToast(r.msg,'error')` 弹出**红色错误**。账其实已修好，用户却以为失败。

### 目标
- 结转状态只有一个判定点，四态化；
- 三个消费方给出一致且可执行的提示；
- 「重新结转」修好账后不再误报红；
- 不自动删除/重建凭证（沿用"store 层拒绝、UI 层确认重做"的既有约定）。

---

## 方案：单点四态判定 + 消费方统一

### 状态机
| state | 条件 | 含义 |
|---|---|---|
| `none` | 无 carryPL 凭证 且 净额=0 | 本期无损益发生 |
| `todo` | 无 carryPL 凭证 且 净额≠0 | 需要结转 |
| `ok` | 有 carryPL 凭证 且 净额=0 | 已结转且仍有效 |
| `stale` | 有 carryPL 凭证 且 净额≠0 | **结转凭证与当前损益不一致（本次要修的核心态）** |

## 改动清单

### 1. `js/store.js` —— 新增单点判定
在 `carryForwardState`（≈L2560-L2563）之后新增，**保留 `carryForwardState` 原样不动**（红字冲销 L2143、`hasCarryForward`、`tools/import_check.js` 仍在用）：

```js
// 本期结转损益的四态判定 —— 唯一判定点，供 settleChecklist / carryForwardProfit / 批量生成共用。
// 此前各消费方各自判断（一个只看"是否有结转凭证"、一个只看"净额是否为零"），
// 在"结转凭证仍在、但其对应损益凭证已被删改"时会给出相反结论（详见 CHANGELOG 2026-09-29）。
carryForwardStatus: function (month) {
  var vs = this.periodVouchersOfKind(month, this.VOUCHER_KINDS.CARRY_PL);
  var net = this.periodProfitNet(month);
  var need = Math.abs(net.rev) >= EPS || Math.abs(net.exp) >= EPS;
  var exists = vs.length > 0;
  var nums = vs.map(function (v) { return (v.word || '转') + '-' + v.no; }).join('、');
  return { state: exists ? (need ? 'stale' : 'ok') : (need ? 'todo' : 'none'),
           exists: exists, need: need, vouchers: vs, nums: nums, net: net };
}
```

### 2. `js/store.js` —— `carryForwardProfit` 守卫（≈L2572-L2588）
把 `periodProfitNet` 取值**提到幂等判断之前**，按四态分流；给所有返回补 `state` 字段（机器可读，UI/测试不再靠正则）：

- `isPeriodClosed` → `{ok:false, state:'closed', msg:'该月已结账，请先反结账'}`（守卫仍在最前）
- `exists && !need` → **保持原文案** `'本期损益已结转，请勿重复；如需重做请先删除结转凭证（' + nums + '）'`，`state:'ok'`
- `exists && need` → 改为 `'本期结转凭证与当前损益发生额不一致，请点「重新结转损益」重新生成（将先删除旧结转凭证 ' + nums + '）'`，`state:'stale'`
- `!exists && !need` → 保持 `'本期损益净额为零，无需结转'`，`state:'zero'`
- 正常结转成功 → 保持 `{ok:true, vouchers, totalRev, totalExp, net}`，加 `state:'done'`

> 措辞刻意**不断言成因**：plug 配平（L2629-L2640）在极端汇总下也会让结转后立即不结平，"重新结转"可能复发，故用中性的"与当前损益发生额不一致"。
> **绝不自动删除/重建凭证。**

### 3. `js/store.js` —— `settleChecklist` carry 项（≈L2901-L2912）
改用 `carryForwardStatus(month)`；**`!need` 分支文案一行不动**（正常已结转月靠 `hasPLActivity` 显示「损益已结转（本期损益净额已清零）」，不能改）：
- `!need` → `ok`（原文案，两种变体保持）
- `need && exists`（stale）→ `fail`，`'本期结转凭证与当前损益发生额不一致，请点「重新结转损益」重新生成（将先删除旧结转凭证 ' + nums + '）'`
- `need && !exists`（todo）→ `fail`，`'本期损益未结转，请先结转损益'`（原文案）

`closePeriod` 拼接的 msg 会自动带上新文案，无需改动。

### 4. `js/pages/settle/Settle.js` —— 「重新结转」不再误报红（L190-L214）
删完旧凭证后按 `r.state` 分流反馈：
- `r.state === 'zero'` → 视为**成功**：`showToast('已作废过时结转凭证 ' + old.length + ' 张：本期已无损益发生，无需结转', 'success')`，照常 `refreshSettle(); syncAll();`
- 其余 `!r.ok` → 仍 `showToast(r.msg, 'error')`（真失败）
- 成功路径的 toast（L210-L211）保持不变

### 5. `js/pages/settle/Settle.js` —— 批量生成不再静默跳过（L341-L343）
仅动 profit 分支，dep/cost 判断不变：

```js
var existed = S.periodVouchersOfKind(month, sysKindMap[g.id]);
if (existed.length) {
  if (g.id === 'profit' && S.carryForwardStatus(month).state === 'stale') {
    errCount++; msgs.push('结转损益：本期结转凭证已过时，请点「重新结转损益」重新生成');
  } else { skipCount++; }
  continue;
}
```

> 批量生成**不自动删凭证**（勾选式批处理无声删账风险太高），只把「静默跳过」变成「明确提示」。

- [`attemptClose` L364-L376](file:///Users/chen/财务软件/ty/tools/test_newbook_fuzz.js#L364-L376)：`blockedByCarry` 与"重做结转"的判据改用 `c.state === 'stale'`（比正则可靠）

- [孤立结转用例 L540-L542](file:///Users/chen/财务软件/ty/tools/test_newbook_fuzz.js#L540-L542)：`/请先删除结转凭证/` → `c1.state === 'stale' && /重新结转/.test(c1.msg)`

## 明确不做（含理由）
- **不自动删除/重建结转凭证**：沿用既有约定（`genCostVoucher`/`carryYearEnd`/`profitDist` 都是"拒绝 + 提示先删旧凭证"，由 UI 确认后重做）。
- **不在删除损益凭证时加预警**：结账清单已给出明确出口；且删除是两个 UI 入口（[Voucher.js L1157](file:///Users/chen/财务软件/ty/js/pages/voucher/Voucher.js#L1157)、[L1759](file:///Users/chen/财务软件/ty/js/pages/voucher/Voucher.js#L1759)）都不接 `hint`，改动面大于收益，且会变成天天弹的噪音。
- **不改 `periodProfitNet` / `carryForwardState` 口径**：两者各自正确，问题只在消费方。
- **不动 CHANGELOG.md**：已被 `.gitignore:53` 排除，不属代码改动。

## 风险
- **已结账月也可能停在 stale**（通过结账检查项降级 + `force` 结账的既有入口）：此时 `carryForwardProfit` 的 `isPeriodClosed` 守卫在最前，返回「该月已结账，请先反结账」，行为正确，无需额外处理。
- `carryForwardProfit` 新增的 `state` 字段是**纯增量**，老调用方（`tools/sim_book.js`/`pl_check.js`/`audit25.js`/`verify_e2e_snapshot.js`）只判 `ok`，不受影响。
