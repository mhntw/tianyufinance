# 金额定点化（×10000）+ 取数索引第二步 实施方案

## 一、Context：为什么要做

**浮点金额已经在制造真实缺陷。** `js/store.js` 文件头（L16-44）自记了 4 起事故，全部源于浮点：漏一次 `round2` 就导致「差 0」被误判为不相等；有人试图把 `EPS` 从 0.005 放大到 0.01（等于放行真不平）。这不是理论风险。

**实测真实账套（只读扫描 `~/Library/Application Support/添钰财务/books/`）**：

| 账套 | 小数位分布 | >2 位小数的值 |
|---|---|---|
| 添钰来客（0.98MB） | 1位 824 / 2位 2712 / 3位 1 / 4位 1 / 11~12位 4 | 6 处 |
| 绅蓝之星（1.81MB） | 1位 1595 / 2位 4868 / 3位 2 / 10~16位 40 | 41 处 |

两类性质完全不同：

- **真·4 位定点值**（×10000 的收益所在）：`fixedAssets[0].salvage = 339.1485`、`248.669`、`vouchers[2486].entries[2].dr = 2051.6644444444446`（4 位值被除摊成循环小数）。**集中在固定资产折旧摊分**。
- **浮点表示噪声**（`995288.7100000002`、`65359.729999999996`）：占多数，值是对的、表现是错的 —— 正是 4 起事故的来源。定点化能**根除**这一类。

**精度损失发生在入口**：[kis-import.js:256-257](file:///Users/chen/财务软件/ty/js/kis-import.js#L256-L257) 解析时就 `Math.round(×100)/100` 砍到 2 位，所以金蝶源数据的 4 位精度**从未落盘**。因此定点化必须同时改这处截断，否则只换了内部表示、拿不回精度。

**性能**：取数索引第一步已完成（新增 `_invalidate()` 单一失效入口 + `_vchIndexOf()` 按月索引，真实账套 1.8×：报表页 166ms→95ms）。第二步（`openingOf` 的分录累计索引）待做。

**已确认决策（用户已拍板）**：① 全量定点化，含导入不再截断；② 界面金额仍显示 2 位；③ 老账套自动迁移 + 迁移前先写备份。

## 二、关键判断：执行顺序 = 先定点化，后索引第二步

**这与先前「先索引、后定点化」的建议相反，我改判了**，理由有两条且都可验证：

1. **索引第二步在浮点域无法被严格验证。** 它的核心是「按科目累计发生额」的求和次序变化，而浮点加法**不可结合**：索引路径与逐科目路径的结果会在低位不同，影子对照只能退化成「round2 后逐分相等」—— 而 `round2` 容差恰恰就是本次要消灭的东西。改在整数域做，则「索引路径 === 逐科目路径」可以断言**精确相等**，验证强度高一档。
2. **避免写两遍。** 定点化必然要改 `openingOf` / `generalLedger` 内部的 `beforeDr/Cr`、`periodDr/Cr`、`ytdDr/Cr` 三处累计；先做索引等于写完再改写。

代价：残余 68ms 的性能问题多留一段时间（当前页面 ~95ms，不构成阻塞）。索引**第一步已完成且与金额类型无关**（它只做数组筛选与排序），不因改判而返工。

## 三、阶段划分

### 阶段 0：建立干净基线（前置，必须先做）

- **验证**：`node tools/run-all.js` 51 通过 / 2 跳过 / 0 失败。

### 阶段 1：定表示约定（只加不改，系统仍可运行）

- **做什么**：在 [store.js](file:///Users/chen/财务软件/ty/js/store.js) 内（**不新增文件** —— `store.js` 在 `kis-import.js`/`ty-io.js` 之前加载，`num/money` 已在同一处定义，新增文件反而要改加载顺序）确定并落定底座：
  - `AMT_SCALE = 10000`；内部金额 = 0.0001 元的**安全整数**；磁盘同单位。
  - `amt(v)`：唯一**外部**金额解析入口（字符串/浮点 → 整数），负数按对称 half-away-from-zero（`Math.round(-0.5)` 是 `-0`，非对称，必须显式处理）。
  - `yuan(a)`：整数 → 元（仅用于导出/图表边界）。
  - `money(a)`：改为入参整数 → 显示 2 位千分位；舍入在**整数域**完成（`Math.round(a/100)` 对称化），不先除再舍入（规避 0.5 分边界）。显式消 `-0`。**并在函数首行加硬断言**：`Number.isSafeInteger(a) || 抛错/显式告警` —— 把「漏改一处导致放大 10000 倍」从静默错误变成可见错误。
  - `U.money` 与全局 `money` 指向同一实现（报表页走 `U.money`，两套不能分叉）。
  - `round2()` 降级为导出/显示边界的薄封装并标注 deprecated；`EPS` 的**语义**改为严格相等。
- **验证**：`node --check`；`run-all` 全绿（本阶段不改行为）。
- **回滚点**：新增函数无人调用，直接删。

### 阶段 2：单次原子改造（**中途不可运行，一个提交**）

- **顺序**（全改完才可运行）：
  1. 金额解析调用点：**逐处分类 116 个 `num(` 调用**（`grep -c 'num(' js/store.js`）为三类 —— ① 内部整数传递（`num` 恒等，保留）② 外部解析（改用 `amt`）③ 非金额（数量/期间/比率，不动）。**禁止一刀切保留 `num`**，②类漏改就会留下浮点半定点态。
  2. 计算层：`voucherBalance`、`openingBalanceCheck`、`openingOf`、`generalLedger`、`subjectEndBalance`、`subjectPeriodAmount`、`detailLedger`、`opening`/`setOpening`、结转损益、折旧摊分、工资。
  3. 容差比较 → 严格相等（详见第四节风险 3）。
  4. 显示层：`money()` 语义切换后，**所有传参处**同步改（页面裸调 `money()`、报表 `U.money()`、`js/pages/home/Home.js` 的 `fmt()`、`js/report/_shared.js`）。
  5. **导出边界 ÷10000**：`js/ty-io.js` 的 `fmt`、报表导出、`xlsx.full.min.js` 的 `aoa_to_sheet` 喂数点 —— 漏一处就是 Excel 里金额放大 10000 倍，而用户会拿它去报税。
- **避免半定点中间态**：收支两端在同一提交内换单位；`money()` 的整数断言在阶段 2 期间即生效（任何漏改点当场暴露）。
- **验证**：阶段 3 的影子对照工具 + `run-all` + 真实账套 `verify_invariants`。
- **回滚点**：单个提交，`git revert` 即回到阶段 1 结束态。

### 阶段 3：影子对照工具（与阶段 2 同一提交交付）

- **做什么**：新增 `tools/verify_amount_shadow.js`（文件名匹配 `^(test|verify|check|sim)_` 才会被 `run-all` 收录）。
  - **旧实现来源**：`git show <阶段0基线>:js/store.js` 取旧源码文本，注入浏览器桩（`window=global`、localStorage/document 桩）与**定向 `require`**（把 `./standards.js` 解析到 `js/standards.js`）后执行，得到旧 `S_old`；`persist/addLog/backupNow` mock 为空。**不落盘、不污染仓库**。退路：写到 `os.tmpdir()` 临时文件再 require。

### 阶段 4：存量迁移（`SCHEMA_VERSION` 5 → 6）

- **检测点**：`store.js` 的 `loadCurrentBookFromDisk` 中 `self.state = res` **之前**插入 `_migrateToV6(res, bookId)`。当前该处把版本不一致交给 `window.__onSchemaMismatch` 弹 UI（L740-763）；改为：**磁盘=5 且程序=6 → 自动迁移**，其余不一致仍走原钩子。
- **链路（顺序不可颠倒）**：
  1. `Storage.saveRestoreSnapshot(bookId, 原始文本)` → **校验 `ok===true`，否则中止迁移、保留旧内存、报错横幅**（复用 [storage.js](file:///Users/chen/财务软件/ty/js/storage.js#L126-L152) 的备份机制；与既有 `_saveBookChecked` 的写法一致）
  2. 迁移内存副本 → 3. `Storage.saveBook` 落盘 → 4. **回读 `loadBook` 校验 `schemaVersion===6`** → 5. 才替换 `self.state`，并调 **`_invalidate()`**（复用本轮已建的单一失效入口）+ 重跑 `normalizeState` / `ensureVoucherIds` / `ensureCashFlowFields` → 6. 跑 `runSelfTest`，不过则以快照回滚。
- **迁移写法：按字段白名单 ×10000，绝不递归**（递归必炸）。白名单：

| 乘 10000 | 禁乘 |
|---|---|
| `vouchers[].entries[].{dr,cr}` | `schemaVersion`、`no`/`word` |
| `openingBalances[].{dr,cr,yb,ytdDr,ytdCr}` | `subjects[].{level,sortOrder}`、科目编码 |
| `fixedAssets[]` 的 `original/salvage/impairment/accumDepr*/yearDepr/netValueBegin/netValueEnd` 及 `history[]`、折旧明细 `lines[].amt` | `assetCats[].{life,salvageRate}`、`fixedAssets[].{life,salvageRate,periodUsed,status,cleanPeriod,method}` |
| `payrolls[]` 的金额项 | `company.startMonth`、`param.*`、`closedPeriods` |
| `cashFlowOpening[].ytd`、现金流量项目金额 | `reportRules` 全部（含 `codes`/`minus`） |
| **凭证模板 `entries` 的金额**（`vchTemplates`/`settleTemplates`/`salaryVchTpls`，易漏） | 期间数、数量类字段 |

- **幂等**：迁移后立即置 6，二次进入直通（防重复 ×10000）。
- **验证**：迁移前后 `verify_invariants.js` 全绿 + `runSelfTest` 通过；新增 I17「迁移幂等：v5 账套迁移两次结果字节相同」。
- **回滚点**：迁移前快照即回滚物。**v6 → 5 不做自动降级**（会重新丢精度）；真正回滚 = 用「恢复备份」载入迁移前的 v5 快照（新程序会自动再迁一次，等价于回到迁移前数据状态），或退回旧程序版本读该快照。

### 阶段 7：索引第二步（在整数域落地）

- **做什么**：一次遍历全部分录，建 `月份 × 科目` 发生额矩阵并做前缀和；`openingOf` 从 O(科目数 × 全部分录数) 降为 O(rollCodes)；`generalLedger` 的 `periodDr/Cr`、`ytdDr/Cr` 两处同类循环同样改读矩阵。
- **复用**：失效挂在已建的 `_invalidate()` 上（**不新增机制**）；矩阵挂在 `_vchIndexOf()` 同一生命周期内，随凭证数组引用/长度变化自动重建（含 `verify_gl_cache.js` 那种「只换数据不调 store」的路径）。
- **验证**：与逐科目路径**整数精确相等**（这正是把它排在定点化之后的原因）+ `run-all`；再复测性能（目标：残余 68ms → ~10ms 量级）。

## 四、风险清单（按「算错钱 × 静默」排序）

1. **迁移误乘非金额字段**（`reportRules`、`salvageRate`、`life`、`periodUsed`）→ 白名单 + 迁移后 `runSelfTest` + `verify_invariants` 全绿才放行，否则快照回滚。
2. **导出未 ÷10000** → Excel 金额放大 10000 倍，用户拿去报税 → 加「导出后读回 xlsx 校验单元格」断言。
3. **容差比较残留**：定点化后一切金额比较应严格相等。必须改的点（按函数名）：`voucherBalance`、`openingBalanceCheck`、`runSelfTest`、`carryForwardProfit` 的差额判断、试算平衡与资产负债表恒等式 diff、现金流量勾稽、`importExternalBook` 跨年差异、固定资产折旧核对、`kis-import` 差异比较。过渡手法：`EPS = 0`（`<= 0` ≡ `=== 0`）与改判据同一批完成。
4. **半定点中间态** → 阶段 2 单提交 + `money()` 整数断言 + 启动即校验底座存在。
5. **旧程序打开 v6 账套**（放大 10000 倍）：不可完全消除 → 迁移前快照留 v5 原样 + 迁移后横幅「本账套已升级，请更新程序」。
6. **除不尽的分摊/折旧**：整数域必须定义舍入与余数归属（末笔承接），并把这批值列入影子对照白名单，逐条写明原因。
